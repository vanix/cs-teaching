時脈頻率 (Clock Frequency) 與 時脈週期 (Clock Period)

CPU 內部有一個像心臟一樣脈動的「石英晶體振盪器」，發出持續高低電位交替的脈衝訊號（Clock Signal）。 CPU 內部的所有微指令（如寫入暫存器、邏輯運算）都必須配合時脈的上升緣（Rising Edge）或下降緣進行同步。

時脈週期 (Clock Cycle Time, T)
T = 1 / f

完成一個方波脈衝所需要的時間（常用單位：ns 微秒, ps 奈秒）

時脈頻率 (Clock Rate / Frequency, f)
f = 1 / T

一秒鐘內震盪發出的時脈週期次數（常用單位：MHz, GHz）

核心知識：為什麼頻率越高，CPU 執行速度越快？

假設執行一個指令固定需要 4 個時脈週期（Clock Cycles）：

  • 在 1.0 GHz 時脈下：1 個週期為 1.0 ns，執行該指令耗時 4.0 ns。
  • 在 2.0 GHz 時脈下：1 個週期縮短為 0.5 ns，執行該指令僅需 2.0 ns！

👉 總結： 頻率越高，代表單位時間內（每秒）能完成的週期次數越多，單個週期的持續時間越短，CPU 就能在更少的時間內處理完相同數量的指令！

MIPS (Million Instructions Per Second) 指標介紹

MIPS 代表每秒機能執行多少「百萬個指令」。它是早期衡量電腦 CPU 執行速度最直觀的效能指標之一。

指令數 (Instruction Count, IC)

程式編譯後所包含的總機械指令數量，取決於 ISA 指令集架構與編譯器優化。

CPI (Cycles Per Instruction)

平均每個指令需要消耗多少個時脈週期。不同指令（如 ADD vs. DIV）所需 CPI 不同。

執行時間 (Execution Time, CPU Time)

執行該程式總共花費的秒數：
Time = (IC × CPI) / Frequency

📐 MIPS 換算公式完整推導 (Mathematical Formulas)

公式 1：基於總指令數與執行時間
MIPS = 指令總數 (IC) / (執行時間 (s) × 10⁶)
公式 2：基於時脈頻率與平均 CPI (極常考！)
MIPS = 時脈頻率 (MHz) / CPI
= (時脈頻率 (GHz) × 1000) / CPI

為什麼不能只看 MIPS 判定 CPU 效能好壞？(MIPS 的局限)

1. 忽略了指令能力的差異： CISC（如 x86）的一條複雜指令可能完成 RISC（如 ARM/MIPS）三條指令的工作。RISC 的 MIPS 值可能很髙，但實際完成相同任務時間並不一定比較快！
2. CPI 非常數： 不同的程式（如浮點運算 vs. 整數邏輯）CPI 差異極大，因此 MIPS 無法反映 CPU 跨應用的真實表現。

CPU 機械週期 (Machine Cycle) 32-Bit 微觀模擬

直觀展示 CPU 處理 32 位元二進位指令的四大歷程：1. 擷取 (Fetch) 32-bit 二進位碼 ➔ 2. 解碼 (Decode) 匡選欄位並辨識算式 ➔ 3. 執行 (Execute) ALU 運算 ➔ 4. 儲存 (Store/Writeback) 寫回記憶單元。

示範指令:
1. 擷取 (FETCH)

從 RAM 載入 32 位元二進位指令碼到指令暫存器 (IR)。

2. 解碼 (DECODE)

控制單元 (CU) 匡選二進位位元，辨識指令類型與操作數。

3. 執行 (EXECUTE)

ALU 算術邏輯單元接收數值並執行算術/邏輯計算。

4. 儲存 (STORE)

將計算出的結果寫回暫存器 R3 或記憶體單元中。
